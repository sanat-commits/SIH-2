# Coding Rules

## Absolute rules

1. No hardcoded query-to-agent routing.
2. No hardcoded query-to-tool routing.
3. No hardcoded sample answers.
4. No hardcoded execution outputs.
5. No hardcoded document names.
6. No hardcoded source counts.
7. No hardcoded citations.
8. No document-specific extraction branches.
9. No fixed agent sequence.
10. No hidden operational limits.
11. No unrestricted Python execution.
12. No external network calls in sovereign mode.
13. No secrets in source code.
14. No cross-task state.
15. No final answer generated by a tool that should return evidence.
16. Tool outputs must be structured.
17. Errors must propagate as structured failures.
18. Configuration must be validated at startup.
19. Schemas must be shared rather than duplicated.
20. Every agent/tool must be discoverable through a registry.

## Preferred design

Use:
- dependency injection
- adapters
- typed schemas
- configuration providers
- capability descriptors
- structured events
- explicit provenance
- deterministic infrastructure code
- model-driven decisions only where reasoning is appropriate

## Do not create

- giant `router.py` with query keyword checks
- giant `agent.py` containing every tool
- document-specific if/else blocks
- hardcoded fallback answers
- duplicated registries
